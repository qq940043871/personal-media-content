## 二、核心问题：高维向量检索

### 1. 问题定义

向量检索的核心任务可以表述为：

> **在高维空间中，快速找到与查询向量最相近的 K 个向量（即 KNN，K-Nearest Neighbors 检索）。**

所谓"相近"，通常通过向量之间的距离度量来衡量，常见的度量方式包括：

| 度量方式 | 说明 | 适用场景 |
|---|---|---|
| **余弦相似度（Cosine Similarity）** | 衡量两个向量方向的夹角，值域 [-1, 1]，越接近 1 越相似 | 文本语义检索、推荐系统 |
| **欧氏距离（L2 Distance）** | 衡量两个向量在空间中的直线距离，越小越相似 | 图像特征匹配、通用检索 |
| **内积（Inner Product）** | 向量点积，综合考虑向量的方向与模长 | 归一化向量的近邻搜索 |

### 2. 暴力检索的瓶颈

最直觉的方法是**暴力检索（Brute Force Search）**——对库中每一条向量逐一计算与查询向量的距离，然后取距离最近的 K 条返回。

让我们用一个具体例子来感受暴力检索的开销：

```
假设：
- 数据规模：1000 万条向量（10M vectors）
- 向量维度：768 维（常见的 BERT 输出维度）
- 查询延迟要求：< 100 ms

暴力检索需要的操作：
- 每次查询计算 1000 万次 768 维的余弦相似度
- 即 1000 万 × 768 = 76.8 亿次浮点运算
- 即使 GPU 加速，单次查询延迟也难以满足要求
```

**结论**：当数据规模达到百万级以上时，暴力遍历的计算开销在工程上完全不可接受。我们必须为向量数据建立**索引（Index）**，通过巧妙的数据结构设计来大幅减少每次查询需要比较的向量数量，从而实现高效的近似最近邻搜索（ANN, Approximate Nearest Neighbor）。

## 三、主流索引类型（工业界两大类）

当前工业界（包括 Milvus、Faiss、Pinecone、Weaviate 等主流向量数据库）广泛采用的索引类型主要分为两大类：**基于图的索引** 和 **基于聚类的索引**。下面我们逐一进行深入讲解。

### 1. HNSW（Hierarchical Navigable Small World）

| 维度 | 说明 |
|---|---|
| **结构原理** | 多层跳表式的图结构（Hierarchical Navigable Small World Graph） |
| **查询方式** | 从顶层开始，贪心向下逐层逼近 |
| **优势** | 查询速度非常快，召回率可达 90%+ |
| **劣势** | 内存开销大 |

#### 结构原理详解

HNSW 的设计灵感来源于两个经典理论：

- **跳表（Skip List）**：一种多层链表结构，高层链表提供"快速通道"，低层链表保证精确遍历。
- **可导航小世界图（Navigable Small World Graph）**：图中任意两点之间存在"快捷路径"，使得贪心搜索可以高效逼近目标。

HNSW 将两者结合，构建了一个**多层的近邻图结构**：

```
Layer 2 (最顶层，节点最稀疏)：  A ------→ F ------→ K
                                 ↘         ↗          ↘
Layer 1 (中间层)：          B → D → F → H → K → M
                              ↘  ↗   ↘  ↗   ↘  ↗
Layer 0 (最底层，包含全部节点)：C → D → E → F → G → H → I → J → K → L → M → N
```

- **顶层**：只保留少量"枢纽"节点，相邻节点之间的距离较远，形成**长程连接**，便于快速定位目标的大致区域。
- **底层**：包含全部向量节点，每个节点与其最近邻相连，形成**短程连接**，用于精确逼近目标。

#### 查询过程

1. 从**最顶层**的入口点出发；
2. 在当前层中，贪心选择距离查询向量最近的邻居节点，逐步移动；
3. 当无法在当前层找到更近的节点时，**下降到下一层**；
4. 重复步骤 2-3，直到到达**最底层**；
5. 在最底层中搜索并返回 K 个最近邻。

这种"从粗到细、逐层逼近"的策略，使得 HNSW 的查询复杂度接近 **O(log N)**，效率极高。

#### 性能表现

- **查询速度**：通常在毫秒级完成千万级数据的检索。
- **召回率**：在合理设置参数（如 `M`、`efConstruction`、`efSearch`）的情况下，召回率可达 **90%~99%**。
- **内存开销**：由于需要存储完整的图结构（每个节点维护多个邻居连接），内存占用较大。粗略估算，每条 768 维 float32 向量本身占约 3 KB，而 HNSW 图结构的额外内存开销可能再增加 **30%~50%**。

### 2. IVF（Inverted File，倒排文件索引）

| 维度 | 说明 |
|---|---|
| **结构原理** | 先将所有向量聚类为数百~数千个簇（Coarse Quantizer） |
| **查询方式** | 仅访问距离最近的若干个簇 |
| **优势** | 内存占用省 |
| **劣势** | 召回率下降，需调节 **nprobe** 参数（查询时访问的簇数量） |

#### 结构原理详解

IVF 的核心思想是**"分而治之"**——通过聚类将整个向量空间划分为若干个区域，查询时只在最相关的少数区域内搜索。

构建过程如下：

1. **训练阶段（Training）**：
   - 使用 K-Means 等聚类算法，将所有向量划分为 **nlist** 个簇（Coarse Quantizer）。
   - 通常 nlist 的取值为几百到几千，例如 `nlist = 1024`。

2. **索引阶段（Indexing）**：
   - 将每条向量分配到距离其最近的簇中。
   - 生成一个"倒排列表"结构：**簇 ID → 该簇内所有向量的 ID 列表**。

```
倒排列表示例：

Cluster 0: [vector_3, vector_17, vector_42, vector_89, ...]
Cluster 1: [vector_1, vector_25, vector_56, vector_103, ...]
Cluster 2: [vector_7, vector_31, vector_68, vector_95, ...]
...
Cluster 1023: [vector_5, vector_40, vector_77, vector_120, ...]
```

#### 查询过程

1. 计算查询向量与所有 **nlist** 个**簇中心**的距离；
2. 选择距离最近的 **nprobe** 个簇（nprobe ≤ nlist）；
3. 仅在这 nprobe 个簇内的向量中进行精确或近似的距离计算；
4. 返回 K 个最近邻。

#### 关键参数：nprobe

`nprobe` 是 IVF 索引中最核心的调优参数：

| nprobe 取值 | 效果 |
|---|---|
| **较小**（如 nlist 的 1%~5%） | 查询速度快，但可能遗漏目标向量，**召回率降低** |
| **较大**（如 nlist 的 10%~50%） | 召回率提高，但查询速度变慢 |
| **nprobe = nlist** | 退化为暴力检索，召回率 100%，但速度最慢 |

> **实际经验值**：一般将 nprobe 设为 nlist 的 1%~10%，在速度与召回率之间取得较好的平衡。例如 nlist=1024 时，nprobe 可设为 16~64。

#### 性能表现

- **内存占用**：相比 HNSW，IVF 无需存储图结构，内存开销显著降低。
- **召回率**：由于只搜索部分簇，召回率通常低于 HNSW，需要通过增大 nprobe 来补偿。
- **适用场景**：数据量较大、内存资源有限、对延迟有一定容忍度的场景。

## 四、工程实践：IVF-PQ 量化压缩

在实际生产环境中，向量数据的规模往往非常庞大。即使采用 IVF 索引来减少搜索范围，存储所有原始向量（如 1000 万条 768 维 float32 向量 ≈ 28 GB）仍然会占用大量内存。为了进一步降低资源消耗，业界广泛采用 **IVF-PQ** 组合方案。

### 1. 组合方案：IVF + PQ

**PQ（Product Quantization，乘积量化）** 是一种向量压缩技术，其核心思想是：

> 将高维向量拆分为若干低维子向量，分别进行独立的量化编码，从而将原始高维浮点向量压缩为紧凑的短码表示。

```
PQ 压缩过程示例（假设向量维度 d = 768）：

步骤 1：将 768 维向量拆分为 m = 96 个子向量（每个 8 维）
步骤 2：对每个子空间独立进行 K-Means 聚类（通常 k = 256，即 8 bit 编码）
步骤 3：每个子向量用一个 8 bit 的码本索引表示

压缩前：768 维 × 32 bit（float32） = 24,576 bit ≈ 3,072 字节
压缩后：96 个子空间 × 8 bit（uint8） = 768 bit = 96 字节
压缩比：约 32:1
```

**IVF-PQ 的完整流程**：

1. **IVF 聚类**：将向量空间划分为 nlist 个簇；
2. **PQ 量化**：对每个簇内的向量进行乘积量化编码；
3. **查询**：先通过 IVF 定位候选簇，再通过 PQ 近似距离计算快速排序返回结果。

### 2. 压缩效果

| 指标 | 数值 |
|---|---|
| **存储格式转换** | float32 → int8（短码表示） |
| **内存节省比例** | 约 **75%** |
| **精度损失** | 召回率下降约 **1~3 个百分点** |

### 3. 精度与资源的权衡

```
方案对比（以 1000 万条 768 维向量为例）：

┌──────────────┬──────────┬──────────┬──────────────┐
│   索引方案    │ 内存占用  │ 召回率   │ 查询延迟      │
├──────────────┼──────────┼──────────┼──────────────┤
│ 暴力检索     │  ~28 GB  │  100%    │  > 数秒       │
│ HNSW         │  ~35 GB  │  95-99%  │  1-10 ms      │
│ IVF          │  ~28 GB  │  85-95%  │  5-50 ms      │
│ IVF-PQ       │  ~7 GB   │  92-97%  │  5-50 ms      │
└──────────────┴──────────┴──────────┴──────────────┘
*以上数据为典型估算值，实际表现取决于参数配置和硬件环境
```

### 4. 适用场景

IVF-PQ 方案特别适合以下生产环境：

- ✅ **对内存敏感**：需要在有限内存中承载大规模向量数据；
- ✅ **可接受小幅精度损失**：1~3 个百分点的召回率下降在业务上可以接受；
- ✅ **大规模生产部署**：数据量达到千万乃至亿级时，内存成本是核心考量因素；
- ✅ **混合使用**：也可以对热点数据使用 HNSW，冷数据使用 IVF-PQ，实现分层存储。

## 五、要点总结

让我们回顾本节课的核心知识点：

1. **向量检索的核心挑战**是高维空间中的近邻搜索效率。当数据规模达到百万级以上时，暴力遍历不可行，必须建立索引。

2. **HNSW（分层可导航小世界图）**：
   - 基于多层跳表式图结构，从顶层贪心下降查询；
   - **速度优先**，查询延迟低，召回率高（90%~99%）；
   - 代价是**内存开销大**。

3. **IVF（倒排文件索引）**：
   - 通过 K-Means 聚类将向量空间划分为多个簇，仅搜索最近的 nprobe 个簇；
   - **内存优先**，存储开销低；
   - 需要合理调节 **nprobe** 参数，在速度与召回率之间取得平衡。

4. **IVF-PQ（量化压缩）**：
   - 生产环境中的**常用方案**；
   - 通过乘积量化将 float32 压缩为 int8，内存节省约 **75%**；
   - 以约 **1~3 个百分点**的精度损失换取**大幅内存节省**。
